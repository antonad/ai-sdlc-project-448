# config-transfer Specification

## Purpose
Экспорт и импорт конфигурации в JSON-файл. Формат описан в `src/app/config-file.ts`, файл проверяется целиком до изменения данных.

## Requirements

### Requirement: Формат файла
Файл конфигурации MUST быть JSON-объектом с целым числом `version` и списками `users`, `groups`, `services`, `permissions`. Разрешение MAY содержать необязательные поля `startsAt` и `expiresAt` (строки `ГГГГ-ММ-ДДTчч:ммZ`, UTC). Экспорт MUST писать `version` 4; файлы версий 1, 2, 3 и 4 принимаются. Один и тот же формат MUST использоваться для экспорта, импорта и хранения в браузере. Неизвестные поля SHALL игнорироваться.

#### Scenario: Круговой обмен
- **WHEN** конфигурация экспортирована и импортирована обратно
- **THEN** получается равная конфигурация

#### Scenario: Круговой обмен со сроками
- **WHEN** экспортирована конфигурация с постоянным разрешением, разрешением с интервалом и разрешением с одной границей, и файл загружен обратно
- **THEN** получается равная конфигурация, границы сохранены, у постоянного разрешения полей нет

#### Scenario: Неизвестные поля
- **WHEN** в файле есть дополнительные поля
- **THEN** файл принимается, лишние поля отбрасываются

#### Scenario: Пустая конфигурация
- **WHEN** все четыре списка пусты
- **THEN** файл принимается

#### Scenario: Файл версии 1
- **WHEN** загружен файл с `version` 1, где у разрешений нет полей срока
- **THEN** `import-status` сообщает «Конфигурация заменена», все разрешения постоянные, доступ считается так же, как раньше, на любой момент

#### Scenario: Файл версии 2 с датами
- **WHEN** загружен файл с `version` 2, где у разрешения `startsOn` равно 2026-12-01 и `endsOn` равно 2026-12-14
- **THEN** файл принимается, разрешение получает `startsAt` 2026-12-01T00:00Z и `expiresAt` 2026-12-15T00:00Z, доступ есть весь 14.12.2026 по UTC и нет с 2026-12-15T00:00Z

#### Scenario: Файл версии 3 без пояса
- **WHEN** загружен файл с `version` 3, где `startsAt` равно 2026-12-01T09:00 и `expiresAt` равно 2026-12-14T18:00
- **THEN** файл принимается, значения читаются как UTC: `startsAt` 2026-12-01T09:00Z, `expiresAt` 2026-12-14T18:00Z, в любом часовом поясе браузера

#### Scenario: Версия экспорта
- **WHEN** администратор нажимает «Экспортировать»
- **THEN** в файле `version` равна 4, у разрешений со сроком поля `startsAt` и `expiresAt` с суффиксом `Z`

#### Scenario: Сохранённая копия версии 1
- **WHEN** в `localStorage` лежит конфигурация версии 1, 2 или 3
- **THEN** она читается с переводом полей как UTC, не заменяется учебными данными и доступ считается так же, как до перевода

### Requirement: Стадии проверки
Ошибки MUST собираться в список, а не только первая, в пределах одной стадии. Стадий три, каждая следующая выполняется только если предыдущая не нашла ошибок: (1) JSON, объект в корне, целая `version` не новее поддерживаемой, при ошибке возвращается ровно одна причина; (2) форма записей и уникальность идентификаторов во всех четырёх списках; (3) ссылки разрешений и участия в группах.

#### Scenario: Несколько ошибок
- **WHEN** в файле больше одной ошибки одной стадии (например, две битые ссылки)
- **THEN** экран показывает все ошибки списком

#### Scenario: Ошибки разных стадий
- **WHEN** в файле есть и ошибка формы записи, и битая ссылка
- **THEN** показываются только ошибки формы; ссылки проверяются после их исправления

### Requirement: Атомарный импорт
При ошибке в файле текущая конфигурация и сохранённая копия в браузере MUST остаться прежними. Частично применённого файла SHALL NOT быть. При успехе конфигурация заменяется целиком и сохраняется.

#### Scenario: Файл с ошибкой
- **WHEN** загружен файл со ссылкой на несуществующего пользователя
- **THEN** экран показывает «Файл не принят, конфигурация осталась прежней» и список ошибок, разрешения и значение в `localStorage` прежние

#### Scenario: Успешный импорт
- **WHEN** загружен корректный файл
- **THEN** экран сообщает «Конфигурация заменена», данные сохранены в браузере

#### Scenario: Исправление после ошибки
- **WHEN** после отвергнутого файла загружен корректный
- **THEN** он принимается, сообщение об ошибке исчезает

### Requirement: Экспорт
Экран MUST давать выгрузить текущую конфигурацию файлом на устройство пользователя в формате файла импорта.

#### Scenario: Выгрузка
- **WHEN** администратор нажимает «Экспортировать»
- **THEN** скачивается JSON с текущей конфигурацией

### Requirement: Проверка файла с моментами целиком
Система MUST проверить весь файл до изменения конфигурации. Идентификаторы в списке SHALL быть уникальными, ссылки разрешений и участия в группах MUST указывать на существующие записи. Версия новее поддерживаемой MUST отвергаться. Поля `startsAt` и `expiresAt` версии 4, если заданы, MUST быть реальными моментами в формате `ГГГГ-ММ-ДДTчч:ммZ`, а окончание MUST быть строго позже начала. Эти проверки относятся к стадии формы записей.

#### Scenario: Ошибка формата
- **WHEN** файл не JSON, не объект, без целой версии, без списка или с записью неправильной формы
- **THEN** файл отвергнут, причина указывает место (например `users[1]`)

#### Scenario: Битая ссылка
- **WHEN** разрешение ссылается на несуществующего пользователя, группу или сервис, либо пользователь состоит в несуществующей группе
- **THEN** файл отвергнут с описанием ссылки

#### Scenario: Дубль идентификатора
- **WHEN** в списке повторяется идентификатор
- **THEN** файл отвергнут

#### Scenario: Версия новее поддерживаемой
- **WHEN** в файле `version` равна 5
- **THEN** файл отвергнут с причиной про версию

#### Scenario: Несуществующий момент
- **WHEN** у разрешения `expiresAt` равно `2026-02-30T10:00Z` или `2026-03-01T25:00Z`
- **THEN** файл отвергнут, причина указывает место `permissions[N].expiresAt`

#### Scenario: Неверный формат момента
- **WHEN** у разрешения версии 4 `startsAt` равно `2026-03-01T09:00` без `Z`, `2026-03-01` без времени, `01.03.2026 09:00` или не строка
- **THEN** файл отвергнут, причина указывает место `permissions[N].startsAt`

#### Scenario: Окончание не позже начала
- **WHEN** у разрешения `expiresAt` раньше `startsAt` или равно ему
- **THEN** файл отвергнут, причина указывает разрешение `permissions[N]`

#### Scenario: Ошибка момента оставляет данные прежними
- **WHEN** загружен файл с невалидным моментом
- **THEN** экран показывает «Файл не принят, конфигурация осталась прежней» и список ошибок, разрешения и значение в `localStorage` прежние

### Requirement: Поле revokedAt в файле
Разрешение в файле конфигурации MAY содержать необязательное поле `revokedAt` (строка `ГГГГ-ММ-ДДTчч:ммZ`, UTC), дополняющее поля `startsAt` и `expiresAt`. Экспорт MUST писать его у отозванных разрешений. Если поле задано, оно MUST быть реальным моментом, строго позже `startsAt` и строго раньше `expiresAt` (когда они заданы). Файл без поля, в том числе прежних форматов, принимается: разрешение считается неотозванным.

#### Scenario: Круговой обмен с отзывом
- **WHEN** экспортирована конфигурация с отозванным разрешением и файл загружен обратно
- **THEN** получается равная конфигурация, `revokedAt` сохранён

#### Scenario: Прежний файл без revokedAt
- **WHEN** загружен файл прежнего формата без `revokedAt` и без временных разрешений
- **THEN** `import-status` сообщает «Конфигурация заменена», доступ считается так же, как раньше, кнопок отзыва нет

#### Scenario: Неверный момент отзыва
- **WHEN** у разрешения `revokedAt` равно `2026-02-30T10:00Z` или не строка
- **THEN** файл отвергнут, причина указывает место `permissions[N].revokedAt`

#### Scenario: Отзыв вне интервала
- **WHEN** `revokedAt` не позже `startsAt` или не раньше `expiresAt`
- **THEN** файл отвергнут, причина указывает разрешение `permissions[N]`, конфигурация и сохранённая копия остаются прежними

### Requirement: Импорт сохраняет отзывы
При успешном импорте отзыв, сделанный в текущей конфигурации, MUST сохраниться: если в файле есть разрешение с тем же `id`, субъектом, сервисом, `startsAt` и `expiresAt`, у которого нет `revokedAt` или он позже, оно MUST получить `revokedAt` из текущей конфигурации. Остальные разрешения SHALL браться из файла без изменений. Без отзыва в текущей конфигурации файл применяется как есть. Файл с ошибками MUST отвергаться целиком, как прежде.

#### Scenario: Файл, выгруженный до отзыва
- **WHEN** временное разрешение подрядчика выгружено, затем отозвано кнопкой `permission-revoke-<id>`, затем загружен тот же файл через `import-input`
- **THEN** `import-status` сообщает «Конфигурация заменена», разрешение остаётся отозванным, `access-result` на момент после отзыва внутри интервала отвечает «Доступа нет», `access-sources` не показывается, без действий человека

#### Scenario: Тот же файл без отзыва
- **WHEN** тот же файл загружен, а в текущей конфигурации разрешение не отозвано
- **THEN** `access-result` внутри интервала отвечает «Доступ есть»

#### Scenario: Другая выдача под тем же id
- **WHEN** в файле разрешение с тем же `id`, но другим сервисом, субъектом или интервалом
- **THEN** отзыв не переносится, разрешение берётся из файла как есть

#### Scenario: Два отзыва
- **WHEN** в файле у разрешения свой `revokedAt`, а в текущей конфигурации другой
- **THEN** действует более ранний момент

#### Scenario: Файл с ошибкой
- **WHEN** загружен файл с ошибкой, а в текущей конфигурации есть отзыв
- **THEN** файл отвергнут целиком, конфигурация и сохранённая копия прежние, отзыв на месте
