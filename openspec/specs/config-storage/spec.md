# config-storage Specification

## Purpose
Хранение конфигурации только в браузере пользователя. Серверной части нет, данные никуда не отправляются.

## Requirements

### Requirement: Конфигурация только в браузере
Конфигурация MUST храниться в `localStorage` под ключом `access-policy-simulator:config` в формате файла экспорта. Приложение MUST NOT отправлять конфигурацию по сети: в `src` SHALL NOT быть `fetch`, `XMLHttpRequest`, `navigator.sendBeacon` и `WebSocket`. Только слой приложения MAY обращаться к хранилищу.

#### Scenario: Изменения переживают перезагрузку
- **WHEN** администратор меняет разрешения и перезагружает страницу
- **THEN** изменения сохранены

#### Scenario: Только статические файлы
- **WHEN** пользователь работает со всеми экранами
- **THEN** браузер запрашивает только статические файлы приложения

### Requirement: Учебные данные по умолчанию
Если сохранённой конфигурации нет, она повреждена или нарушает ссылочную целостность, система MUST использовать учебные данные. Недоступное или переполненное хранилище MUST NOT прерывать работу.

#### Scenario: Пустое хранилище
- **WHEN** ничего не сохранено
- **THEN** загружаются учебные данные

#### Scenario: Повреждённое сохранённое
- **WHEN** сохранённый текст не разбирается или нарушает целостность
- **THEN** загружаются учебные данные

#### Scenario: Хранилище недоступно
- **WHEN** чтение или запись в `localStorage` бросает ошибку
- **THEN** приложение продолжает работу, при чтении используются учебные данные

#### Scenario: Недоступно само обращение к хранилищу (известное ограничение)
- **WHEN** уже получение `window.localStorage` бросает исключение (например, `SecurityError` при заблокированных данных сайта)
- **THEN** поведение не определено: обращение `window.localStorage` в `src/app/index.ts` стоит вне `try`, поэтому устойчивость гарантирована только для ошибок `getItem` и `setItem`. Не покрыто тестом

### Requirement: Автоматическая проверка границ
Запрет сетевых вызовов в `src` и обращения к `localStorage` из компонентов MUST проверяться правилами ast-grep (`rules/architecture.yml`, `npm run lint:arch`).

#### Scenario: Что проверяется автоматически (текущее состояние)
- **WHEN** запускается `npm run lint:arch`
- **THEN** проверяются сетевые вызовы во всём `src` и `localStorage` в `src/components`; для `src/domain` правила на `localStorage` нет, а запросы браузера во время работы не проверяются
