# Proposal

## Why

Администратор экспортировал конфигурацию, затем отозвал временное разрешение подрядчика, а позже загрузил сохранённый файл, чтобы вернуть другие правки. Импорт заменяет конфигурацию целиком, поэтому в старом файле у разрешения нет `revokedAt`, и отзыв исчезает: закрытый доступ снова открыт, без единого сообщения. Отзыв был сознательным решением и не должен теряться молча (подрядчик студии «Северная», репозиторий).

## What Changes

- При успешном импорте отзыв, сделанный в текущей конфигурации, переносится на то же разрешение из файла. «То же» значит полное совпадение `id`, субъекта, сервиса, `startsAt` и `expiresAt`: id вида `p5` выдаются заново, одного id мало.
- Если у разрешения в файле свой `revokedAt`, действует более ранний из двух моментов (отзыв только сужает доступ).
- Если в текущей конфигурации отзыва нет, файл применяется как раньше: доступ внутри интервала остаётся.
- Файл с ошибками по-прежнему отвергается целиком, конфигурация и сохранённая копия не меняются.
- Идентификаторы `data-testid` не меняются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `config-transfer`: импорт сохраняет отзывы текущей конфигурации.

## Impact

- `src/app/permissions.ts`: новая чистая операция переноса отзывов; `src/app/index.ts`: `importJson` применяет её после проверки файла.
- Тесты рядом с кодом: `permissions.test.ts`, `Permissions.test.tsx`. Затрагиваются СБ 2 (проверка до изменений) и СБ 3 (меняются только совпавшие разрешения).
- Вне изменения: возвращение удалённых кнопкой «Удалить» разрешений через импорт, отмена отзыва.
