# Spec Delta

## MODIFIED Requirements

### Requirement: Атомарный импорт
Импорт MUST идти в два шага: выбор файла и отдельное подтверждение. При ошибке в файле текущая конфигурация и сохранённая копия в браузере MUST остаться прежними. Частично применённого файла SHALL NOT быть. До подтверждения конфигурация и сохранённая копия MUST оставаться прежними, при подтверждении конфигурация заменяется целиком и сохраняется.

#### Scenario: Файл с ошибкой
- **WHEN** загружен файл со ссылкой на несуществующего пользователя
- **THEN** экран показывает «Файл не принят, конфигурация осталась прежней» и список ошибок, предпросмотра нет, разрешения и значение в `localStorage` прежние

#### Scenario: Успешный импорт
- **WHEN** выбран корректный файл и нажата кнопка `import-confirm`
- **THEN** экран сообщает «Конфигурация заменена», данные сохранены в браузере

#### Scenario: Исправление после ошибки
- **WHEN** после отвергнутого файла выбран корректный
- **THEN** открывается предпросмотр, сообщение об ошибке исчезает

### Requirement: Импорт сохраняет отзывы
При подтверждении импорта отзыв, сделанный в текущей конфигурации, MUST сохраниться: если в файле есть разрешение с тем же `id`, субъектом, сервисом, `startsAt` и `expiresAt`, у которого нет `revokedAt` или он позже, оно MUST получить `revokedAt` из текущей конфигурации. Остальные разрешения SHALL браться из файла без изменений. Без отзыва в текущей конфигурации файл применяется как есть. Отзыв, сделанный при открытом предпросмотре, MUST сохраниться так же. Файл с ошибками MUST отвергаться целиком, как прежде.

#### Scenario: Файл, выгруженный до отзыва
- **WHEN** временное разрешение подрядчика выгружено, затем отозвано кнопкой `permission-revoke-<id>`, затем выбран тот же файл через `import-input` и нажата `import-confirm`
- **THEN** `import-status` сообщает «Конфигурация заменена», разрешение остаётся отозванным, `access-result` на момент после отзыва внутри интервала отвечает «Доступа нет», `access-sources` не показывается, без действий человека

#### Scenario: Тот же файл без отзыва
- **WHEN** тот же файл выбран и подтверждён, а в текущей конфигурации разрешение не отозвано
- **THEN** `access-result` внутри интервала отвечает «Доступ есть»

#### Scenario: Другая выдача под тем же id
- **WHEN** в файле разрешение с тем же `id`, но другим сервисом, субъектом или интервалом
- **THEN** отзыв не переносится, разрешение берётся из файла как есть

#### Scenario: Два отзыва
- **WHEN** в файле у разрешения свой `revokedAt`, а в текущей конфигурации другой
- **THEN** действует более ранний момент

#### Scenario: Файл с ошибкой
- **WHEN** загружен файл с ошибкой, а в текущей конфигурации есть отзыв
- **THEN** файл отвергнут целиком, конфигурация и сохранённая копия прежние, отзыв на месте

#### Scenario: Отзыв при открытом предпросмотре
- **WHEN** выбран файл, снятый до отзыва, при открытом предпросмотре разрешение отозвано, затем нажата `import-confirm`
- **THEN** разрешение остаётся отозванным

## ADDED Requirements

### Requirement: Предпросмотр импорта
После выбора файла через `import-input`, прошедшего проверку, экран MUST показать контейнер `import-preview` с кнопками `import-confirm` и `import-cancel`, а `import-status` не показывать. Различия разрешений MUST называться строками своего вида: `import-preview-added-<id>` для разрешения, которого сейчас нет и которое появится, `import-preview-removed-<id>` для текущего разрешения, которого после подтверждения не будет, `import-preview-changed-<id>` для разрешения с тем же `id` и другим содержимым. Строки разрешений MUST совпадать с различиями разрешений между конфигурацией до и после подтверждения, других строк о разрешениях быть SHALL NOT. Если подтверждение сохранит отзыв текущего разрешения, которого нет в файле, предпросмотр MUST содержать строку `import-preview-kept-<id>`, и такое разрешение не называется ни убранным, ни изменённым. Если ничего не изменится, предпросмотр MUST содержать `import-preview-empty` и ни одной строки добавленных, убранных и изменённых разрешений. Различия пользователей, групп и сервисов показываются сводкой `import-entities`.

#### Scenario: Предпросмотр корректного файла
- **WHEN** выбран файл, прошедший проверку
- **THEN** показаны `import-preview`, `import-confirm`, `import-cancel`, `import-status` и `import-error` не показаны

#### Scenario: Выданные, убранные и изменённые
- **WHEN** после экспорта выдано разрешение `p6`, удалено `p5`, а в файле у `p3` изменён сервис
- **THEN** в предпросмотре ровно три строки: `import-preview-added-p5`, `import-preview-removed-p6`, `import-preview-changed-p3`, а после подтверждения конфигурация равна файлу

#### Scenario: Сохраняемый отзыв
- **WHEN** в текущей конфигурации `p6` отозвано, а в файле отзыва нет
- **THEN** в предпросмотре есть `import-preview-kept-p6`, разрешение не названо ни убранным, ни изменённым

#### Scenario: Файл совпадает с конфигурацией
- **WHEN** выбран файл, равный текущей конфигурации
- **THEN** в `import-preview` есть `import-preview-empty`, строк выданных, убранных и изменённых разрешений нет

#### Scenario: Предпросмотр ничего не меняет
- **WHEN** предпросмотр открыт
- **THEN** `access-result` отвечает как до выбора файла, файл по `export-link` равен прежнему, набор ключей и значений `localStorage` не изменился

#### Scenario: Перезагрузка страницы
- **WHEN** страница перезагружена при открытом предпросмотре
- **THEN** `import-preview` скрыт, `access-result` отвечает как до выбора файла

#### Scenario: Подтверждение
- **WHEN** нажата `import-confirm`
- **THEN** показан `import-status`, скрыт `import-preview`, `access-result` отражает импортированную конфигурацию

#### Scenario: Отмена
- **WHEN** нажата `import-cancel`
- **THEN** скрыты `import-preview` и `import-status`, `access-result`, экспорт и `localStorage` равны прежним

#### Scenario: Ошибка после предпросмотра
- **WHEN** при открытом предпросмотре выбран файл с ошибкой, затем корректный
- **THEN** сначала показан `import-error` без `import-preview`, затем `import-preview` без `import-error`
