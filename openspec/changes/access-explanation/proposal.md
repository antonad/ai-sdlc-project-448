# Proposal

## Why

Марина видит ответ «Доступ есть» или «Доступа нет» и список действующих источников. Когда доступа нет, показан только список неактивных разрешений, а когда доступ есть, неактивные не видны вовсе. Чтобы понять, почему пара (сотрудник, сервис) получила такой ответ на выбранный момент, нужны все разрешения пары разом: действующие, ещё не начавшиеся, истёкшие и отозванные. Это отдельный пункт требований продукта и без него расследование «почему у него (нет) доступа» приходится вести по панели разрешений вручную.

## What Changes

- Под ответом о доступе появляется блок «Объяснение доступа». Он виден, когда выбраны сотрудник и сервис, и перечисляет каждое разрешение пары на выбранный момент расчёта: источник (прямое разрешение или группа) и статус (действует, ещё не началось, истекло, отозвано).
- Для пары без разрешений блок сообщает «Разрешений для этой пары нет».
- Состав строк и статусы вычисляет домен одной функцией, а `calculateAccess` строится поверх неё. Так число действующих строк по построению совпадает с результатом расчёта.
- Существующие списки `access-sources` и `access-inactive` остаются без изменений.

Вне рамок: правка разрешений из блока объяснения, объяснение для нескольких пар сразу, история изменений, показ разрешений, которые не относятся к паре, изменение формата файла и хранилища.

Затронутые требования СБ: объяснение читает конфигурацию и ничего не меняет, не пишет в хранилище и не ходит в сеть (ограничение «данные остаются в браузере» не нарушается). Архитектурные правила: расчёт только в `src/domain/access.ts`, момент приходит параметром `at`, компоненты берут всё из `src/app`.

## Impact

- `src/domain/access.ts`: новая чистая функция `explainAccess`, `calculateAccess` использует её; публичный результат `calculateAccess` прежний.
- `src/app/index.ts`: реэкспорт типов и функции, метод хука `explainAccess(userId, serviceId, moment)`.
- `src/components/App.tsx`: блок «Объяснение доступа».
- Тесты рядом с кодом: `src/domain/access.test.ts`, `src/app/*.test.ts`, `src/components/App.test.tsx`.
- Документация: `docs/product.md` (сценарий объяснения).
