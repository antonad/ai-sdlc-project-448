# Design

## Context

Мотивация и требования: `proposal.md`, дельты в `specs/`.

Что есть сейчас: `revokePermissionFrom(config, id, moment)` в `src/app/permissions.ts` сокращает `expiresAt`; панель показывает поле момента в каждой строке; расчёт в `src/domain/access.ts` знает две причины недействия: `not-started` и `expired`. Формат файла version 3 хранит `startsAt` и `expiresAt`.

Ограничения: расчёт доступа только в `src/domain/access.ts` и без часов; компоненты берут всё из `../app`; импорт проверяется целиком; операции меняют только выбранное разрешение, независимые источники сохраняются (СБ 2, СБ 3, СБ 4).

## Goals / Non-Goals

**Goals:**
- Отзыв виден в данных отдельным полем и не искажает срок, с которым разрешение выдали.
- Одна общая точка ввода момента отзыва на панели.

**Non-Goals:**
- Отмена отзыва, история отзывов, отзыв будущего интервала до его начала.
- Изменение версии файла: поле необязательное.

## Decisions

### Поле `revokedAt` вместо сокращения `expiresAt`

Отзыв записывает `revokedAt = момент`, `startsAt` и `expiresAt` остаются как были. Альтернатива «сокращать `expiresAt`» отвергнута требованием: нужна отметка отзыва, видимая в экспорте. Версия файла не растёт: старые файлы читаются без поля, новое поле для них необязательное.

### Расчёт: `revokedAt` как досрочное окончание

Разрешение действует в минуту `key`, если `startsAt <= key`, `key < expiresAt` и `key < revokedAt` (пустые границы не ограничивают). Порядок причин для недействующего: `not-started`, затем `revoked` (если `revokedAt` раньше `expiresAt` и `key >= revokedAt`), затем `expired`; если срок кончился раньше отзыва, причина остаётся `expired`. Причина `revoked` несёт границу `revokedAt`. Домен не читает часы и не знает о версиях файла.

### Отказы отзыва

`revokePermissionFrom(config, id, moment)` возвращает `{ config, result }`. Порядок проверок: `invalid-moment`, `unknown-permission`, `permanent` (у разрешения нет ни `startsAt`, ни `expiresAt`), `already-revoked`, `not-after-start` (`moment <= startsAt`), `already-ended` (`expiresAt <= moment`). При отказе возвращается та же ссылка на конфигурацию. Операция добавляет `revokedAt` ровно одному разрешению через `map` со spread.

Выбор «только с интервалом»: у постоянного разрешения отзыв по требованиям недоступен (кнопки нет), поэтому операция тоже отказывает, а не дублирует `removePermission`.

### Файл конфигурации

`readInterval` читает необязательное `revokedAt` (проверка момента). Дополнительно: `revokedAt` строго позже `startsAt` и строго раньше `expiresAt`, если они заданы, иначе файл отвергается с указанием `permissions[N]`. Версия остаётся 3.

### Панель

Одно поле `permission-revoked-at` (`datetime-local`, по умолчанию пустое) и кнопка `permission-revoke-<id>` в строках разрешений с интервалом без `revokedAt`. Момент отзыва: значение поля, иначе `evaluation-time`, иначе текущий момент. `evaluation-time` приходит в `PermissionsPanel` пропсом из `App` (состояние уже в `App`), часы читает слой приложения через `nowMoment`. После успеха сообщение «Разрешение отозвано», строка остаётся и показывает «отозвано с ДД.ММ.ГГГГ чч:мм» (`permission-revoked-<id>`). Идентификаторы прошлого шага отзыва (`-open-`, `-date-`, `-confirm-`) удаляются.

## Risks / Trade-offs

- **Два способа ограничить срок.** `expiresAt` и `revokedAt` вместе: действует более ранний. Смягчение: тесты на оба порядка и проверка файла (`revokedAt` строго внутри интервала).
- **Переименование идентификаторов отзыва.** Тесты прежнего шага придётся обновить.
- **Отзыв ещё не начавшегося интервала запрещён** (`not-after-start`): такое разрешение удаляют кнопкой удаления.
