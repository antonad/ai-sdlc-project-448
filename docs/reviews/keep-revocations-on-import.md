# Ревью изменения keep-revocations-on-import

База: коммит `70a9373` (ветка main). Дифф: `git show 70a9373`, сверка с `openspec/changes/keep-revocations-on-import/` (proposal, design, tasks, `specs/config-transfer/spec.md`), `docs/architecture.md` и `docs/security-requirements.md`. Тесты и проверки в этой сессии не запускались, только чтение кода.

Нарушений требований СБ и архитектуры нет. Есть две мелкие находки.

## Что проверено

- **Не то разрешение / открытие доступа.** `sameGrant` (`src/app/permissions.ts:123`) требует совпадения `id`, субъекта (тип и id через `sameSubject`), `serviceId`, `startsAt`, `expiresAt`. Идентификаторы в файле уникальны (`config-file.ts:21`), поэтому `find` однозначен. При различии любого поля отзыв не переносится, разрешение берётся из файла. Перенесённый момент лежит внутри того же интервала, поэтому проходит проверку файла и круговой обмен. Более ранний из двух отзывов выбирается корректно: строки UTC сравнимы лексикографически. Случаев, когда отзыв снимается или доступ открывается дополнительно, не найдено: функция только добавляет или сдвигает `revokedAt` раньше.
- **Домен и часы.** Расчёт доступа не тронут (`src/domain` не менялся), часы не читаются, момент не нужен. Слой `app` импортирует из `domain` только типы. `components` в коммите не менялись, `data-testid` не переименованы (тесты используют существующие).
- **Атомарность (СБ 2).** `importJson` (`src/app/index.ts:97-105`) вызывает `carryOverRevocations` только после `ok` от `parseConfigFile`; при ошибке возврат до `replace`. Экранный тест (`Permissions.test.tsx`, «файл с ошибкой отвергается целиком») проверяет, что `localStorage` и отзыв прежние.
- **СБ 3.** Функция чистая: исходные `current` и `imported` не мутируются (тест с `structuredClone`), остальные разрешения, пользователи, группы и сервисы берутся из файла как есть, при отсутствии переносов возвращается та же ссылка `imported`.
- **СБ 1, сеть и localStorage.** Новых обращений нет.
- **Покрытие сценариев спеки.** Все пять сценариев есть: файл до отзыва (юнит и экран, включая `import-status`, `access-result`, `access-sources`), тот же файл без отзыва (оба уровня), другая выдача под тем же `id` (юнит), два отзыва (юнит, обе стороны), файл с ошибкой (экран). Экранного теста на «два отзыва» нет, но юнит-тест его покрывает.

## Известные ограничения (приняты в design.md)

- Разрешение, удалённое кнопкой и возвращённое старым файлом, вернётся без отзыва.
- Отзыв нельзя отменить импортом старого файла.
