# Ревью изменения utc-instants

База: `HEAD`. Дифф: `git diff HEAD` (рабочее дерево, не закоммичено) и неотслеживаемая папка `openspec/changes/utc-instants/`. Номера строк указаны по файлам рабочего дерева. Прогнаны `npm run typecheck`, `npm test` (8 файлов, 292 теста, все зелёные, в том числе при внешнем `TZ=America/Los_Angeles`: `process.env.TZ` из `vite.config.ts` применяется к воркерам), `npm run lint`, `npm run lint:arch`, `npm run build` и `npm run test:coverage` (пороги держатся) — всё с кодом 0. Перевод `localToUtc`/`utcToLocal` дополнительно проверен вручную в `Asia/Yekaterinburg`, `Europe/Berlin` и `America/New_York`.

## Что проверено

- **1. Сценарии дельт спек.** access-calculation: все 11 сценариев «Срок действия» и 3 сценария «Моменты хранятся в UTC» есть в `access.test.ts` (границы 08:59/09:00, 17:59/18:00, секунды, пояс процесса UTC+5 не сдвигает границу, строки 536-560) и `App.test.tsx` (причина «закончилось 14.12.2026 23:00»); «результат не зависит от пояса» подтверждён тестом UTC против локального построения `Date`, перебора поясов нет (в рамках design: тесты идут в фиксированном поясе). permission-management: выдача, отзыв, пустое поле в UTC+5 — в `App.test.tsx`, `permissions.test.ts`, `Permissions.test.tsx`. config-transfer: круговой обмен, версии 1, 2, 3, версия 5, несуществующий момент, момент без `Z` с местом `permissions[N].…`, окончание не позже начала, отзыв вне интервала, копии версий 1–3 и 4 с ошибкой — в `config-file.test.ts`, `storage.test.ts`, `App.test.tsx`.
- **2. Перевод.** Граница суток, месяца и года проверена тестами (`dates.test.ts`: `2026-12-31T23:30Z` → 2027, 29 февраля, начало года) и вручную. UTC+5 без летнего времени даёт ровно ±5 часов, туда и обратно значения совпадают. Берлин: весеннее несуществующее `02:30` читается как `03:30` (принято дизайном), осеннее неоднозначное берёт первое вхождение, обратный перевод стабилен. Края диапазона лет: находка 1. Невалидный `Date` в `minuteKey` из UI недостижим: `momentToDate` строит дату только из проверенных полей или `new Date()`.
- **3. Версии 1-3 и СБ 2.** Версия 3 получает `Z` после проверки `isValidMoment`, версия 2 — `startOfDay`/`startOfNextDay` в UTC (перенос месяца и года), версия 1 — без полей. Строка с `Z` в версии 3 и без `Z` в версии 4 отвергается с местом `permissions[N].поле`. Ошибки накапливаются, проверка границ пары идёт только при валидных границах, `parseConfigFile` ничего не меняет, `importJson` заменяет конфигурацию и хранилище только при `ok`. Доступ в UTC при переводе не меняется (то же число, суффикс `Z`).
- **4. Граница.** `grantPermission`: локальные поля → `intervalError` → `localToUtc` → `addPermission`; `revokePermissionFrom`: `isValidMoment` → `localToUtc` → чистая операция с `isValidUtcMoment`; `checkAccess` через `momentToDate`; двойного и пропущенного перевода нет. `formatMoment`/`formatInterval` вызывают `utcToLocal`, причины и «отозвано …» показывают локальное время (проверено тестами экрана). Порядок проверки границ после перевода: находка 2.
- **5. Слои.** Компоненты берут всё из `../app`, `src/domain`, `localStorage`, `Date`, сеть в них не добавлены; домен часы не читает (`minuteKey(at)` только форматирует переданное `at`); `lint:arch` чист.
- **6. Тесты и пояс.** `process.env.TZ = "Asia/Yekaterinburg"` в `vite.config.ts` применяется к воркерам Vitest (тесты зелёные и при внешнем `TZ=America/Los_Angeles`, значит, переопределение работает), `typecheck`, `lint` и `build` не затронуты. Тесты ловят пропущенный перевод: значения записей сверяются с UTC при вводе в UTC+5. Тавтологий не найдено. Пробел: нет теста на краевые годы и летнее время (находки 1-2).
- **7. СБ 3 и СБ 4.** Операции по-прежнему меняют одно разрешение (`map` со spread, исходный объект не мутируется, при отказе возвращается та же ссылка); перевод не трогает чужие записи; независимые источники (Анна Белова, `p1` и группа) покрыты тестами домена и экрана.
- **8. data-testid.** Прежние идентификаторы не переименованы и не удалены (`permission-starts-at`, `permission-expires-at`, `permission-revoked-at`, `permission-revoke-<id>`, `permission-remove-<id>`, `evaluation-time`, `import-status`).
- **9. Тексты.** «Файл не принят, конфигурация осталась прежней», «закончилось 14.12.2026 23:00», «с 01.12.2026 14:00 до 14.12.2026 23:00», «отозвано с 05.12.2026 17:00», «Окончание должно быть позже начала» совпадают со спеками. Сообщения `intervalError` потеряли часть «в формате ГГГГ-ММ-ДДTчч:мм» (теперь «Начало/Окончание должно быть реальным моментом»); спеки их текст не задают, тесты обновлены. Подсказка файла версии 4 «момент в формате ГГГГ-ММ-ДДTчч:ммZ», версии 3 — прежняя.
- **10. Кодировка.** BOM нет, CR нет, двойной перекодировки кириллицы нет ни в одном изменённом и новом файле; `git ls-files --eol`: новые файлы `w/lf`.

## Вывод

Архивировать можно после решения по находкам 1 и 2 (общее исправление: проверять результат перевода `localToUtc` валидатором UTC и порядок границ уже в UTC) и обновления `docs/architecture.md` (находка 3). Находки 4 и 5 не блокируют. Основная логика (расчёт по UTC, чтение версий 1-3 как UTC, проверка версии 4, перевод на границе) соответствует спекам и дизайну.
