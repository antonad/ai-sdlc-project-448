# Симулятор политик доступа

Учебный проект Хекслета (ai-sdlc). Браузерное приложение: React 19 + Mantine + TypeScript, сборка Vite, тесты Vitest. Серверной части нет.

## Команды

| Что | Команда |
| --- | --- |
| Установка | `npm ci` |
| Dev-сервер (порт 8080) | `npm run dev` |
| Тесты | `npm test` |
| Типы | `npm run typecheck` |
| Линтер и формат | `npm run lint` (исправить: `npm run lint:fix`) |
| Архитектурные правила | `npm run lint:arch` |
| Сборка | `npm run build` |

Перед завершением любой задачи пройти: `npm test`, `npm run lint`, `npm run lint:arch`, `npm run build`. CI (`.github/workflows/ci.yml`) делает то же самое.

## Что прочитать до правок

- `docs/architecture.md`: три слоя (`src/domain`, `src/app`, `src/components`) и три правила импортов и времени.
- `docs/security-requirements.md`: четыре ограничения СБ. Любой дифф сверяется с ними.
- `README.md`: описание продукта и запуск.

## Жёсткие правила

- Расчёт доступа только в `src/domain/access.ts`. Часы не читать, момент приходит параметром `at`.
- Компоненты берут всё из `../app`, включая типы. Не импортировать `src/domain`, не трогать `localStorage`.
- Никаких `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon` в `src`.
- Импорт файла проверяется целиком до изменения данных. Операции меняют только выбранные разрешения.
- Новая логика сопровождается тестом рядом с кодом (`*.test.ts`, `*.test.tsx`).
- Не редактировать, не удалять и не переименовывать `.github/workflows/hexlet-check.yml`.
- Новое архитектурное правило оформляется файлом в `rules/*.yml` (ast-grep) и проверяется `npm run lint:arch`.

## Стиль

- Формат и линт: oxfmt и oxlint, конфиг по умолчанию. Окончания строк LF (`.gitattributes`).
- Тексты интерфейса, сообщения об ошибках и комментарии на русском.
- Работа по спецификации: сначала тест или критерий приёмки, затем код, затем проверки выше.

## Скилы проекта

В `.claude/skills/`: `verify` (полный прогон проверок), `review-diff` (ревью диффа по архитектуре и требованиям СБ), `add-arch-rule` (новое правило ast-grep).
